# 可复用格式模板设计

## 背景

当前投喂源导入文章时会生成 `ArticleFormatProfile`，定时任务通过
`format_profile_id` 固定使用某个格式版本。模板表的 `source_article_id` 已经允许为空，
但界面还没有把已有格式另存为独立模板的入口，因此用户仍需要保留投喂链接才能方便地
选择格式。

本次只补齐常规模板管理入口，不改变既有任务的配置、绑定关系和执行器分支。特别是正式
环境中的“绣蔓仿写”任务必须继续保持 `format_profile_id` 为空时的原有 `feed` 流程。

## 目标

1. 用户可以把已分析的投喂文章格式保存为独立常规模板。
2. 常规模板不再依赖原文章，后续定时任务可以直接显式选择它。
3. 常规模板不会被投喂源的自动绑定逻辑选中。
4. 既有任务和既有模板的数据库字段保持不变。

## 非目标

- 不删除或批量重绑任何现有定时任务。
- 不修改 Worker、文章生成器或发布链路。
- 不复制文章内容、知识库、ERP 图片规则、水印、二维码或公众号账号配置。
- 不在本次引入新的模板表或版本迁移。

## 方案

### 数据模型

复用现有 `article_format_profiles` 表：

- 来源模板：`source_article_id` 指向投喂文章。
- 常规模板：`source_article_id = NULL`。
- 两者都保留相同的 `render_mode`、`template_payload`、`title_policy` 和版本字段。

另存为操作创建一条全新的记录，常规模板从版本 `1` 开始，不修改原记录。复制前校验
模板属于当前租户且处于启用状态；模板名称由用户输入并做非空、长度校验。

### 后端接口

新增 `POST /api/v1/format-profiles/{profile_id}/save-as`：

- 请求体：`name`。
- 响应：完整的格式模板摘要。
- 权限：沿用现有登录和租户隔离依赖。
- 规则：新记录的 `source_article_id` 固定为 `NULL`，不触发任务绑定。

现有 `GET /api/v1/format-profiles` 保持兼容，仅继续返回启用模板；前端根据
`source_article_id` 显示“来源模板”或“常规模板”。

### 前端交互

在投喂源文章的格式状态操作区增加“另存为常规模板”。用户输入名称后调用新接口，
成功后刷新模板列表并提示模板可以在定时任务中显式选择。

定时任务的格式模板下拉框继续调用现有列表接口，不改变表单字段。选项增加类型提示，
并把说明改为：选择模板是固定版式；不选择模板才保留任务现有自动/历史行为。

### 隔离规则

自动绑定服务只允许从 `source_article_id` 非空的投喂文章模板中选择。常规模板只能由
用户在定时任务表单中显式设置 `format_profile_id`，所以新增模板不会污染绣蔓或任何既有任务。

## 测试策略

- 服务层测试：复制后得到新 ID，名称和格式快照正确，来源文章为空，原模板不变。
- API 合同测试：缺少模板、跨租户模板、停用模板和空名称分别返回明确错误。
- 自动绑定测试：常规模板不出现在自动绑定候选中。
- UI 合同测试：出现另存入口、请求路径正确、类型提示存在，且没有批量任务更新逻辑。
- 回归测试：现有格式模板、任务策略和调度执行相关测试继续通过。

## 兼容性保证

本次不修改任何现有 `scheduled_tasks` 行；不执行数据迁移；不改变
`scheduled_task_executor.py`。如果新增的常规模板从未被任务显式选中，运行结果与改动前完全一致。
