# 图片生成双提供商降级设计

## 目标

将 `gpt-image-2` 作为所有图片生成入口的主模型，并保留通义万相作为故障降级提供商。手动创建文章、定时任务、纯图片流程、即时任务和旧 LangGraph 节点必须共享同一套图片生成入口，避免不同调用路径继续直接依赖万相。

本设计只调整图片生成提供商，不改变正文大模型、视觉理解 Agent、结构化提示词合成、二维码跳过规则、ERP 三天防重复策略和微信公众号发布流程。

## 已验证的中转站协议

中转站使用 OpenAI 兼容协议，基础地址为 `https://zg.baby/v1`。

- 文本生图：`POST /images/generations`。
- 参考图编辑：`POST /images/edits`，参考图片通过 multipart 文件上传。
- 文本生图和参考图编辑均已使用 `gpt-image-2` 完成真实请求。
- 中转站将结果放在 `data[*].url`，但该字段实际为 `data:image/...;base64,...` 数据 URI，而不是公网 URL。
- 因返回结果不是可直接插入文章的网络地址，系统必须解码图片字节并归档到 MinIO，再返回素材 URL 给文章流水线。

## 配置

新增独立图片生成配置，不复用 `DASHSCOPE_MODEL`，因为后者属于正文和分析大模型。

```env
IMAGE_GENERATION_PROVIDER=openai_compatible
IMAGE_GENERATION_BASE_URL=https://zg.baby/v1
IMAGE_GENERATION_API_KEY=
IMAGE_GENERATION_MODEL=gpt-image-2
IMAGE_GENERATION_EDIT_MODEL=gpt-image-2
IMAGE_GENERATION_TIMEOUT_SECONDS=240
IMAGE_GENERATION_FALLBACK_PROVIDER=wanxiang
```

真实密钥只写入被 Git 忽略的 `backend/.env`。`.env.example` 只保留空值或示例值，日志、前端接口、数据库任务参数和设计文档均不得包含密钥。

## 模块边界

### 统一图片生成服务

新增提供商无关的图片生成服务，负责：

- 接收统一的文本生图或参考图编辑请求。
- 先调用主提供商，再根据错误分类决定是否调用降级提供商。
- 返回统一的图片结果对象，包含可用 URL、实际提供商、模型、是否降级和诊断摘要。
- 禁止调用方根据提供商名称自行拼装 HTTP 请求。

统一服务不负责构造文章视觉提示词。视觉 Agent、内容 Agent 和现有提示词合成器仍负责生成最终提示词，图片服务只负责原样传递。

### OpenAI 兼容提供商

新增中转站提供商适配器，负责：

- 文本生图使用 JSON 请求调用 `/images/generations`。
- 图生图下载或读取参考图字节，使用 multipart 请求调用 `/images/edits`。
- 同时兼容 `data[*].url`、`data[*].b64_json` 和真实 HTTPS URL 三种结果。
- 对数据 URI 或 Base64 结果进行严格解码、格式识别、大小限制和 MinIO 归档。
- 返回可被文章预览、素材归档和微信发布链路消费的素材 URL。

适配器不保存 API 密钥，不直接操作文章状态，也不调用微信公众号接口。

### 万相提供商

现有万相调用保留为独立提供商适配器。文本生图继续调用万相文本生图接口；参考图编辑继续使用 `wanx2.1-imageedit`。万相不再被业务代码直接实例化，而是由统一图片生成服务在需要时调用。

### 结果归档

中转站返回 Base64 时，结果先写入 MinIO 的生成图片命名空间。文章后续自动归档、水印和素材库记录继续复用现有服务，避免在提供商适配器中复制素材库业务逻辑。

微信发布时，本地 MinIO 图片继续由现有腾讯 COS 临时中转服务转换为微信中转站可访问的 HTTPS 地址；发布完成后清理 COS 临时对象。

## 调用流程

### 文本生图

1. 调用方提交最终提示词、尺寸和数量。
2. 统一服务调用 `gpt-image-2` 文本生图接口。
3. OpenAI 兼容适配器规范化返回图片并归档 Base64 数据。
4. 成功时直接返回，不调用万相。
5. 可降级故障发生时，以同一最终提示词调用万相。
6. 两个提供商都失败时抛出包含两段诊断信息的异常，禁止随机图库回退。

### ERP 参考图编辑

1. 定时任务按现有规则选择 ERP 产品原图，并生成五至七个不同场景提示词。
2. 统一服务将每个提示词和同一张产品参考图交给 `gpt-image-2` 编辑接口。
3. 中转站请求通过 multipart 上传参考图，不依赖参考图公网 URL。
4. 可降级故障发生时，现有 COS 服务临时公开参考图，再交给万相图生图接口。
5. 任一槽位在两个提供商均失败时，整个文章任务失败，不能发布缺图文章。

## 降级策略

只有下列临时性或服务可用性故障允许降级：

- 连接失败、连接重置、DNS 错误和读取超时。
- HTTP `408`、`409`、`425`、`429`。
- HTTP `500`、`502`、`503`、`504`。
- 成功响应中没有任何有效图片结果。
- Base64 或数据 URI 因上游响应截断而无法完整解码。

下列问题必须直接失败，不调用万相掩盖配置或业务错误：

- HTTP `400`、`401`、`403`、`404`、`422`。
- API 基础地址、密钥或模型配置缺失。
- 参考图片为空、格式不支持或超过允许大小。
- 提示词为空或请求参数不合法。
- 本地 MinIO 归档失败。

每次降级必须写入后端日志，记录主提供商、主模型、失败阶段、错误分类、降级提供商和最终结果，但不得记录密钥、完整 Base64 或完整签名 URL。

## 尺寸兼容

业务层继续使用统一宽高语义。提供商适配器负责转换格式：

- 中转站使用 `1024x1024` 形式。
- 万相使用 `1024*1024` 或现有兼容尺寸形式。
- 中转站不支持的文章长图比例应映射为最接近的受支持比例，不允许因分隔符差异直接失败。

实际使用的尺寸、映射结果和提供商名称写入诊断日志。

## 入口迁移

以下入口必须改为依赖统一图片生成服务：

- HTML 图文仿写。
- 手动创建图文文章。
- 即时纯图片任务。
- ERP 定时图文任务。
- 定时纯图片和视频封面任务。
- 旧 LangGraph 图片生成节点。
- 文章优化、仿写任务和队列任务中的 AI 封面生成。

保留现有 `DASHSCOPE` 前端图片来源值以兼容历史任务，但后端将其解释为“AI 图片生成”，实际提供商由全局配置决定。后续可以新增更准确的 `AI_GENERATED` 枚举，本次不强制迁移已有数据库记录。

## 并发与超时

单次中转站请求超时默认 240 秒。统一服务不在提供商内部无限重试，避免一篇含七张图的文章长时间占用 Worker。主提供商发生一次可降级失败后立即切换万相；万相沿用现有异步轮询上限。

图片槽位继续按现有任务编排顺序处理，先保证稳定性和成本可控。本次不增加跨文章全局并发调度。

## 测试与验收

### 单元测试

- 文本生图请求必须携带 `gpt-image-2` 和完整最终提示词。
- 图生图必须使用 `/images/edits` 并上传参考图字节。
- `data:` URL、`b64_json` 和 HTTPS URL 都能规范化。
- Base64 结果必须写入 MinIO，返回值不能仍是超长数据 URI。
- 临时性错误触发万相降级，鉴权和配置错误不触发降级。
- 主提供商成功时绝不能调用万相。
- 两个提供商都失败时必须抛出明确异常。
- 所有入口最终调用统一服务，不能继续直接实例化万相。

### 集成验收

- 使用 ERP 家具原图生成至少一张换背景图片，产品主体仍可识别。
- 完成一篇含五至七张图片的定时文章并保存到主号草稿箱。
- 后端日志能区分主提供商成功和万相降级成功。
- 模拟中转站超时后，文章能通过万相完成。
- COS 临时对象在成功和失败路径都被清理。
- 二维码参考图继续跳过，其他图片继续仿写。

## 安全和运维

- 中转站密钥只存在于服务端环境变量，并在日志中完全隐藏。
- 对外部参考图下载继续执行 URL 安全校验，禁止访问回环、内网和元数据地址。
- 对 Base64 解码结果设置最大字节数，防止异常响应耗尽 Worker 内存。
- Worker 修改配置或代码后必须重启，Celery Beat 无需因模型切换而修改调度计划。
- 真实密钥已经在聊天中出现，联调结束后应重新生成生产密钥。
