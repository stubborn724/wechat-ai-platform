# 参考图片仿写与二维码过滤设计

## 目标

修正 HTML 图文仿写标题中无语义的末尾连接标点，并让图文仿写、即时纯图片仿写和定时纯图片仿写共用同一套参考图片分析与二维码过滤规则。

## 范围与规则

- 标题槽位在写回 HTML 时移除末尾的 `，`、`、`、`；`、`：`；正文保持原样，避免误删自然表达中的标点。
- 每张参考图片都必须先经视觉理解 Agent 判定是否为二维码。
- 被判定为二维码的图片只跳过自身，不创建提示词、不调用图片生成服务，也不占用其他图片的视觉描述。
- 同一参考内容中的非二维码图片继续按原始顺序仿写。
- 如果全部参考图片都是二维码，流程正常结束且不生成图片；不得退回到通用仿写或空描述生成。

## 架构

`reference_media_analysis_service` 是参考图片分析的唯一入口：它负责按 Markdown 顺序提取图片地址、调用传入的视觉理解函数、以原始索引绑定结果，并过滤二维码。它不访问数据库、不生成图片、不发布内容。

纯图片入口调用共享的图片仿写编排服务。该服务接收已加载的参考文章和业务依赖，复用标题仿写、参考图片分析、提示词构建、万相生成及素材归档。HTTP 创建接口和定时任务只保留各自的查询、持久化与发布职责，避免三处复制 Agent 编排。

HTML 图文仿写保留 DOM 蓝图和原位槽位机制。其图片理解结果同样通过共享的二维码判定规则转换为被排除的图片槽位，保证二维码不会出现在最终 DOM 或图片生成队列中。

## 数据流

1. 入口加载参考文章或参考 HTML。
2. 参考媒体分析服务提取图片并调用视觉理解 Agent。
3. 服务返回带原始索引的可用图片和被跳过二维码的数量。
4. 图文流程从 HTML 蓝图移除二维码槽位；纯图片流程仅遍历可用图片。
5. 每张可用图片构建提示词、生成并归档，随后由入口保存或发布结果。

## 异常与边界

- 图片 URL 为空、视觉理解未返回对象或返回数量不足时，该图片不进入生成队列。
- 图片理解、提示词构建或单张图片生成失败时，记录原因并继续处理其余图片。
- 所有图片均被过滤或生成失败时，不发布空的纯图片文章。
- 视觉理解函数与生成服务以依赖注入形式传入共享编排服务，便于单元测试且避免业务入口耦合具体 Agent。

## 验证

- 标题末尾逗号会被移除，正文末尾逗号保持不变。
- 混合参考图片中二维码被跳过，其余图片的 URL、描述和生成顺序与原始索引一致。
- 所有图片均为二维码时，不调用提示词构建和图片生成。
- 即时纯图片入口和定时纯图片入口都复用同一个仿写编排服务。
