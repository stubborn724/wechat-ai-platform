# 定时 HTML 仿写图片数量配置设计

## 目标

统一定时任务允许为 HTML 版式仿写单独配置生成图片数量。本次测试文章原文有
24 张图片，任务配置为 19，程序保留前 19 个原位图片槽，后 5 个图片节点留空。

## 方案

- 在 `ScheduledTask` 增加 `html_image_count`，取值 1-30，数据库和 API 默认值均为 5。
- 在 `ArticleState` 增加 `max_generated_images`，默认值 5，保持文章创建和历史任务兼容。
- 定时执行器把任务配置写入状态，HTML 内容 Agent 使用该值选择原位图片槽。
- 非 HTML 文章不读取该字段，ERP 图片数量仍由 `erp_image_config.image_count` 管理。
- 定时任务界面在图文任务选中投喂源后显示数字输入，创建、编辑和列表读取使用同一字段。

## 数据与兼容

迁移脚本幂等添加 `scheduled_tasks.html_image_count INT NOT NULL DEFAULT 5`。历史任务、
普通文章入口和未传字段的旧客户端继续按 5 张执行，不扩大已有任务的图片成本。

## 失败处理

API 拒绝小于 1 或大于 30 的值。若参考文章图片少于配置数量，只生成实际存在的
图片槽；若图片生成失败，沿用现有 HTML 发布前完整性校验，不发布带内部槽位标记的正文。

## 验证

- API 模型默认值、范围校验和 ORM 持久化测试。
- HTML Agent 使用 19 张配置并将剩余 5 个槽位置空的回归测试。
- 定时执行器状态透传契约测试与前端源码契约测试。
- 迁移幂等执行、相关 pytest、Python 编译和前端生产构建。
